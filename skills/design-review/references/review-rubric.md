# Review rubric

Use this to organize observation, not to manufacture numerical certainty.

| Dimension | What to look for | Evidence needed |
|---|---|---|
| Task clarity | Purpose, next action, understandable labels, credible content | Visible interface plus actual journey when available |
| Hierarchy | Entry point, emphasis, grouping, scan order, action competition | Rendered view, relevant full-page context |
| Composition | Alignment, proportions, rhythm, useful density, reference fidelity | Comparable viewports/states |
| Type and content | Readability, role consistency, line breaks, realistic lengths | Rendered text, long-content state |
| Color/imagery | Semantic roles, contrast, crop, consistent icon/image language | Actual surfaces/assets; measurements for ratio claims |
| Interaction | Navigation, filters, forms, overlays, recovery and truthful outcomes | Performed actions and observed states |
| Reflow | Ordering, wrapping, reachable actions, local/document overflow | Narrow rendering and zoom/reflow checks |
| Accessibility | Semantics, names, focus, keyboard, motion and announcements | DOM/keyboard/settings checks; screenshots alone are insufficient |

## Finding template

**Severity and location:** user-facing observation in the actual state.
**Impact:** which task/person is affected and why it matters.
**Correction:** specific design or implementation adjustment within the brief.
**Recheck:** viewport, action and expected observable result.

Use severity based on impact: a task blocker, serious friction/access barrier,
or a local polish issue. Do not call every aesthetic preference a blocker.

## Comparison discipline

A baseline/reference must be the actual supplied artifact. Match viewport, content
and state where possible. Explain deliberate deviations rather than claiming a
match from unrelated screenshots. Pixel differences alone cannot decide usability;
an overall aesthetic impression cannot establish pixel fidelity.

If scoring is requested, define the scale and evidence before assigning scores.
Keep untested dimensions unscored. Do not sum a screenshot-only accessibility
guess into a purportedly validated product-quality percentage.
